# ROBOT RESCUE

Cute co-op physics-puzzle game about the Robot Rescue Bureau of Brightwater. Unity 6 LTS, URP.

What's built so far:
- **Milestone 1 (core bot):** PIP's movement, the Tether Cable (power / pull / swing), push / carry / throw,
  a DISPATCH subtitle narrator, and the cooking chamber **Call 2-1: Pasta Emergency**.
- **Milestone 2 (puzzle toolkit):** Helper Drones, conveyors, colour-coded power wires, AND/OR power gates,
  plus three **test chambers** in the Bureau training wing.

Every scene is generated by a one-click editor builder (menu **Robot Rescue**).

## Setup (about 5 minutes)

1. **Unity Hub → New project → Unity 6 LTS (6000.x) → "Universal 3D" template.** Name it `RobotRescue`.
2. Close Unity. Copy this folder's `Assets/_Project/`, `.gitignore`, `.gitattributes` and `README.md` into the new project's root
   (so you get `RobotRescue/Assets/_Project/...`).
3. Reopen the project. Check **Window → Package Manager** has **Input System** installed (the Universal 3D template includes it).
   If Unity asks to enable the new input backend and restart, say yes.
   Also check **Edit → Project Settings → Player → Active Input Handling** is `Input System Package (New)` or `Both`.
4. Menu **Robot Rescue → Build Cooking Chamber Scene** and **Robot Rescue → Test Chambers → Build All**.
   They create the scenes under `Assets/_Project/Scenes/`, their materials and data assets, and add them to Build Settings.
5. Open a scene and press **Play**.

The builder is safe to re-run after you tweak it: data assets update in place and the scene is rebuilt.

## Controls

| Action | Keyboard / mouse | Gamepad |
|---|---|---|
| Move / look | WASD / mouse | Left stick / right stick |
| Jump (also: let go of a swing) | Space | A |
| Pick up / put down | E | X |
| Throw | Left mouse | RT |
| Fire / release Tether | Right mouse | LT |
| Reel in / out (swinging) | Q / Z | RB / LB |
| Restart | Backspace | Select |

The Tether aims at the crosshair, with a small aim-assist cone for gamepads. The crosshair turns green on a valid target.

## Call 2-1: Pasta Emergency (walkthrough)

Nonna Lucia's pasta is still in the box.

1. **Tap:** the sink has no water. Its yellow pressure plate needs more weight than PIP. Push the orange crate onto it.
2. **Fill:** carry the pot under the running tap.
3. **Pasta:** it's on a shelf too high to reach. Tether-pull it down; PIP catches it. (Climbing the crate also works.)
4. **Cook:** put the pot on the stove, plug the Tether into the stove's socket, and drop or throw the pasta in.
   PIP is the battery, so it has to stay within the 7 m cable while the pasta boils (8 s).
5. **Serve:** unplug, carry the cooked pot to Nonna's hatch. The exit door slides open.
6. **Exit:** swing across the harbour gap on the yellow hook (Tether it, swing, jump at the top) to the green flag.

### Toolkit pieces

- **Helper Drone** (`HelperDrone` + `Carryable`): 1 m wind-up cube bot, 1.5 kg (PIP is 1 kg). Carry, throw, pull, stand on it.
  Drones stay upright and centre themselves on a drone below, so stacks are easy. They respawn at their pad if lost.
- **Conveyor** (`Conveyor`): moves loose objects; PIP rides it through `ISurfaceVelocity`, which moving platforms can reuse.
  Runs when powered, or always with `startsOn`.
- **Power wires** (`PowerWire`): floor strips that light up when live. Add them to a source's powered list.
- **Power gates** (`PowerCombiner`, Any/All): use one whenever something has more than one input.
- **Task steps:** `TaskStepSignal` (completes a step when powered) and `TaskStepTrigger` (when PIP walks in).
- Builders share `Editor/ChamberKit` (+ `ChamberKit.Puzzles`): `Drone`, `Socket`, `Plate`, `SlidingDoor`, `Wire`, `Belt`,
  `Gate`, `Hook`, `CheckpointZone`, `StepZone`, `KillPlane`, `ExitFlag`. A new chamber is mostly calls to these.

```
    UI/         PrototypeHUD (IMGUI placeholder)

  Editor/       ChamberKit (shared greybox + puzzle pieces), CookingChamberBuilder, TestChamberBuilder
```

How the pieces talk:

- **Tether Cable** attaches to any `TetherTarget`. The target's `Mode` decides the behaviour:
  `PowerSocket` = Power, `Carryable` = Pull, `TetherAnchor` = Swing. Power and Swing apply a rope-length
  distance constraint to the bot's Rigidbody (no joints, so it stays stable).
- **Power** flows through `IPowerable.SetPowered(bool)`. Sockets and pressure plates power any GameObjects you list;
  stoves, taps and doors implement `IPowerable`. New elements (conveyors, fans) just implement it too.
- **Tasks:** puzzle pieces raise `TaskStepCompleted("step_id")` on the EventBus; `TaskRunner` ticks off the
  `TaskDefinition`'s steps and raises `TaskCompleted`, which opens doors. Rescue Rush can reuse the same definitions.
- **DISPATCH:** anything raises `NarrationCue("cue_id")`; `DispatchNarrator` plays matching lines from a `DispatchScript` asset.
  Cue ids are meant to become Yarn Spinner node names later.
- Bot and held objects use the built-in **Ignore Raycast** layer so the camera, ground check and Tether aim skip them.
  No custom layers or tags needed.

## Status: what's verified and what isn't

- All scripts compile (checked with the C# compiler against Unity reference assemblies and Input System/Editor API stubs).
- **Not yet run inside Unity.** Feel/tuning numbers (speeds, swing gap, cable length, throw arc) are first guesses.
  Things to check on first Play:
  - Test 01: drone steps are 1 m and PIP jumps 1.3 m. If climbing feels too tight, raise `BotController.jumpHeight` a little.
  - Test 02: the crate should ride under the fence slot; PIP shouldn't fit. Check the exit is reachable while plugged in.
  - Test 03: both swings should land with a bit to spare; nudge the hook Z positions in `BuildSwing` if not.
  - Swing gap: if the landing is too hard to reach, lower the hook's Y or move `Landing` closer in the builder (`BuildExit`).
  - Push: the crate should slide at walking pace; tune `BotController.pushForce` / the crate's mass.
  - Water: the pot must pass through the `WaterStream` box under the faucet; widen it if filling feels fiddly.
  - Materials: should be URP Lit. If anything is pink, the project isn't using URP.
- Greybox art (primitives + TextMesh signs) and an IMGUI HUD on purpose; both get replaced in the polish milestone.
